# THE RECEIPT — Prioritized Roadmap

The current MVP is the baseline. This roadmap is intentionally a decision layer, not a request to immediately build every item. With limited remaining credits, prove the loop before adding breadth.

## NOW — strengthen the core loop

| Priority | Candidate | Why now | Cost/complexity |
| --- | --- | --- | --- |
| 1 | Product event vocabulary and lightweight event logging | Measures discovery → first receipt → share → resolution without changing the product surface. This is the cheapest way to learn where the loop breaks. | Low |
| 2 | Real daily streak calculation | Gives daily participation a visible emotional payoff and a strong repeat-use reason. Define timezone and missed-day rules first. | Low–medium |
| 3 | Receipt resolution guardrails | Make “not due yet” and overdue states explicit so the anticipation loop is trustworthy. | Low |
| 4 | Complete the challenged-user response UI | Converts the existing challenge data path into a real social comparison loop. | Medium |

## NEXT — improve retention and social behavior after the core loop is measured

| Candidate | Rationale |
| --- | --- |
| Daily retention view | Use the event vocabulary to understand D1/D7/D30 behavior before building retention mechanics blindly. |
| In-app challenge notifications | A low-cost notification inbox or badge is preferable to external delivery infrastructure at first. |
| Real leaderboard query | Replace demo rows only when enough resolved receipts exist to make ranking meaningful. |
| Share metadata and preview card | Improve link conversion after share clicks are measured; keep the receipt artifact visually consistent. |
| Milestone achievements | Add 10/25/50/100 receipt and streak milestones after streak data is reliable. |

## LATER — interesting but not urgent

- Rich confidence calibration charts.
- Challenge resolution comparisons and rematches.
- Category-specific reputation and collectible receipt views.
- Scheduled daily prompt publishing and editorial tooling.
- Native mobile applications after mobile web behavior is proven.

## DO NOT BUILD YET

Do not add AI chat, AI-generated predictions, AI advice, betting, money, crypto, prizes, payments, subscriptions, ads, complex recommendation systems, advanced moderation, friend graphs, complicated messaging, or enterprise functionality. These introduce cost, safety, moderation, or product-bloat risk without first proving the receipt loop.

## Decision rule

A feature should move forward only if it materially improves discovery, prediction, anticipation, resolution, identity, competition, or sharing—and if its learning value justifies its credit and maintenance cost.
